## 1. 定位与边界

**是什么**：一个 DISC 体系的轻量职业行为风格测评，重点不是「贴标签」，而是看**三种状态下曲线的位移**——
- 自然 → 工作：你戴了什么面具；
- 工作 → 压力：压力下你会变成谁。

**不是什么**：
- 不是心理诊断工具，不提供治疗建议；
- 不是招聘筛选工具，不作为晋升/淘汰依据；
- 不是 MBTI，不使用 MBTI® 名称与量表；
- 不碰甄有才 / BEST / HRforce 的题目、文案与品牌。

## 3. 详细需求

### 3.1 答题流程（P0）

1. 首页：开始测评 / 继续上次（有未完成草稿时置顶并显示进度）/ 历史 / 关于。
2. 三段答题：自然 24 → 工作 12 → 压力 9；每段结束插入一页阶段反馈（「已完成 1/3」）。
3. 每答一题立即写入草稿：`{ answers, cursor, stage, updatedAt, version }`。
4. 退出（关闭页面/切后台）不丢草稿；再次进入提示「继续上次（第 N/45 题）/ 重新开始」。
5. 答完立刻计分并跳报告；草稿转为历史记录。

### 3.2 题库结构（P0，内容待写）

| 段 | 题量 | 题型 | 作用 |
|---|---|---|---|
| 自然状态 | 24 | 每题 4 个描述，分别对应 D/I/S/C；选「最像我」+「最不像我」 | 基线曲线 |
| 工作状态 | 12 | 情境迫选：「在工作中，我通常…」；4 个反应选项各锚定一维，**只选「最像我」** | 角色面具 |
| 压力状态 | 9 | 情境迫选：「被临时加需求 / 被否定时，我会…」；同上，**只选「最像我」** | 压力反应 |

题目要求：
- 全部原创，口语化、具体、不褒不贬；
- 每题四个选项分别锚定一个维度，避免一题多义；
- 工作/压力段不设「最不像」，降低操作成本与噪声；
- 不出现诊断、疾病、疗效相关词。

### 3.3 计分（v0.1 暂定，待盲测校准）

1. 每段独立统计：
   - 自然段：被选「最像」的维度 +2，被选「最不像」的维度 −1；
   - 工作/压力段：只记录被选「最像」的维度 +2，其余为 0，不设负分。
2. 每维得分归一化到 0~100，分母按段区分：
   - 自然：`(raw + 24) / 72 * 100`（raw 范围 −24~48）；
   - 工作：`raw / 24 * 100`（raw 范围 0~24）；
   - 压力：`raw / 18 * 100`（raw 范围 0~18）。
   - 注意：自然段 raw=0（从未被提及）会落在 33 分而非 50 分，曲线解读以**同段内相对高低**与**跨段位移**为主，不把 50 当作中性线。
3. 工作/压力为单选，四维得分之和固定（工作 24 分、压力 18 分），属强制选择（ipsative）：只用于个人内相对比较，不做人际比较；压力段 9 题时单题权重 11%，避免一题把某一维顶满；盲测若出现「四个都不太像我、很难选」，再评估增加「都不太像（0 分）」选项。
4. 主维 = 最高分；次维 = 第二高分；类型代码 = 主维 + 次维（如 `DI`、`CS`）。
5. 类型名从独立命名表取（自建 12 组，避免与甄有才命名重合）。
6. 差异分析：
   - 自然 → 工作：位移最大的维度，标注「上调 / 收敛」；
   - 工作 → 压力：位移最大的维度，标注「放大 / 退化」。
7. 数据不足（某段未完成）时不出该段结论，明确写「这段还没答完」。

### 3.4 报告结构（P0）

| # | 模块 | 说明 |
|---|---|---|
| 1 | 报告头 | 昵称（可选填；不填时取统一账户昵称，未登录为「我」）+ 类型代码 + 类型名 + 日期 |
| 2 | 综合特征 | 8~12 条短句，由「主维 + 次维 + 状态差异」规则模板生成，末尾固定一条「这套风格要留意的代价」 |
| 3 | 三状态曲线 | 同一坐标系画三条线（自然/工作/压力），或三张小图并排 |
| 4 | 三状态画像 | 每状态约 200~300 字，第二人称，具体不空泛 |
| 5 | 差异解读 | 「你的面具」「压力下的你」两小段 |
| 6 | 特别说明 | 不构成心理诊断；不代表优劣；仅供参考 |
| 7 | 维度释义 | D/I/S/C 各一句白话解释，可展开看「生活里的表现 / 说法从哪来 / 参考来源」 |
| 8 | 操作 | 保存分享图 / 查看历史 / 清除我的数据 |

### 3.5 综合特征文案规则（P0）

- 数据来源：主维、次维、三状态位移、各维相对高低。
- 「代价」一条：写在 `TYPE_NAMES[code].cost`，12 型各一句；第二人称、具体场景、不羞辱，用来对冲报告「只夸不提醒」。
- 生成方式：规则模板拼句（`content.js`），可选 AI 润色（P1，失败不影响）。
- 风格：锐利、口语化、有画面感；**不羞辱、不绝对化**（不用「你一定」「你就是」）。
- 与原产品关系：结构可借鉴，**句子必须原创**。

### 3.6 分享图（P0，已完成 v0.16）

- 报告页操作区「生成分享图」→ Canvas 1080×1920：品牌、日期、类型代码 + 类型名 + 一句话、三状态折线缩略、3 条特征、站点名与固定声明。
- `toBlob` 出 PNG；弹出预览层：手机长按保存，电脑点「下载图片」。
- 文件名 `work-persona-{code}-YYYYMMDD.png`；不包含任何他人品牌元素。

### 3.7 历史记录（P0）

**现状**：v0.14 已补齐保存可靠性（唯一 id / 50 条上限 / 写失败保留草稿并可重试）、首页与报告页入口、列表、详情复看（按快照渲染、不重新计分）、与上一条的对比（列表标签 + 详情顶部卡片）。

#### 3.7.1 保存规则

1. 每次完整答完（45 题全部完成）才写入一条历史；中途退出只保留草稿，不产生历史。
2. 写入时机：计分成功 → 生成记录 → 写入 `wp_history` → 删除 `wp_draft`；写历史失败时**不删除草稿**，并提示「保存失败，可先导出/重试」。
3. 记录结构（`schemaVersion` 用于后续兼容）：

   ```json
   {
     "schemaVersion": 1,
     "id": "wp_<时间戳>_<6位随机串>",
     "createdAt": "ISO 时间",
     "nickname": "昵称或账户名或「我」",
     "main": "D", "secondary": "I", "code": "DI", "low": "S",
     "byStage": {
       "natural": { "score": { "D": 0, "I": 0, "S": 0, "C": 0 }, "raw": {}, "main": "D", "secondary": "I", "answered": 24, "total": 24, "complete": true },
       "work":    { "...": "同上结构" },
       "stress":  { "...": "同上结构" }
     },
     "shifts": { "naturalWork": {}, "workStress": {} }
   }
   ```

4. `id` 必须唯一（时间戳 + 随机串），防止连续重测在同一毫秒写入导致覆盖；同一 `id` 只保留一条。
5. 按 `createdAt` 倒序排列，**最多保留 50 条**，超出删除最旧一条。
6. 存储写满时：保留最新 N 条重试写入一次；仍失败则提示「本机存储已满，请清除历史或导出备份」，不静默丢数据。
7. 历史只存本机（`localStorage`），不上传；P1 云同步时并入同一 `history` 数组按 `id` 去重合并。

#### 3.7.2 入口

| 位置 | 表现 | 说明 |
|---|---|---|
| 首页 | 「开始测评 / 重新开始」下方一个次按钮「历史记录（N）」，N 为本地条数 | N=0 时按钮置灰并显示「暂无历史」，不跳空页 |
| 报告页底部 | 操作区第三个按钮「查看历史」 | 与「再测一次 / 回到首页」并列 |
| 历史列表页 | 顶部「← 回到首页」 | 单列布局，复用现有卡片样式 |

#### 3.7.3 历史列表

1. 标题「历史记录」，副文案「共 N 条 · 只保存在本机」。
2. 每条卡片显示：
   - 时间：`YYYY-MM-DD HH:mm`（本地时区）；
   - 类型：类型代码 + 类型名（如 `DI · 冲阵手`）；
   - 三状态摘要：自然 / 工作 / 压力 各一行，显示该段主维 + 次维（如「自然 D>I」）；
   - 对比标签（有上一条时）：「主维不变」或「主维 D → I」。
3. 点击整条进入详情；新→旧排序，最新的在最上面。
4. 空状态：说明「完成一次测评后，记录会出现在这里」，并给「去测评」按钮。

#### 3.7.4 历史详情（完整报告复看）

1. 复用现有报告渲染逻辑，按记录快照渲染，**不重新计分**（保证与当时结果一致）。
2. 顶部增加返回：「← 回到历史」；不在详情页内提供答题/编辑入口。
3. 顶部显示与**上一条**记录的对比卡片（首次记录显示「这是第一条记录，暂无对比」）：
   - 主维：不变 / 由 X 变为 Y；
   - 类型代码：不变 / 由 XY 变为 AB；
   - 自然→工作、工作→压力 两段中位移最大的维度，各给一句方向描述（如「D 上调 12 分」）。
4. 对比对象只取时间上相邻的上一条，不做多选对比。
5. 底部操作：「再测一次」「回到首页」。

#### 3.7.5 不做的范围

- 不做历史单条删除（仅保留整体「一键清除」，归入数据管理 P0）。
- 不做跨记录曲线叠加图、导出单条报告、历史搜索/筛选。
- 不做云端历史（P1 同步再并入）。


### 3.8 维度说明与来源（P0）

**要解决的问题**：现在报告里每个维度只有一句释义，用户不知道 D/I/S/C 从哪来、凭什么这么分。补上「白话解释 + 生活表现 + 公开来源」，让人一次看懂，又不写得像论文。

#### 3.8.1 覆盖范围

- 只覆盖四个维度 D / I / S / C；不逐题写依据，不做 12 类型来源（后续需要再单开）。
- 三段状态（自然 / 工作 / 压力）本轮不加来源说明。

#### 3.8.2 每个维度写四段

| 段 | 内容 | 长度 |
|---|---|---|
| 一句话定义 | 复用现有 `DIMS.desc`，例如「先把方向和节奏定下来，再谈细节」 | ≤30 字 |
| 生活里的你 | 一个具体场景，说明这个维度高的人日常怎么表现 | 1~2 句，≤60 字 |
| 这个说法从哪来 | 用白话说明 DISC 四分类的来源，以及本测评只是借用分类、不照搬他方量表 | 1~2 句，≤70 字 |
| 参考来源 | 中文条目：作者《标题》/ 刊名与年份；点开进站内知识库，不外跳 | 1~2 条 |

- 每维展开后正文合计 ≤200 字（不含来源行），默认收起，避免报告变长。
- 说明只解释维度，不预测职业、收入、绩效，也不出现「你是高 D 所以一定…」的绝对化句式。

#### 3.8.3 来源口径

1. 只引**中文公开来源**：中文版理论著作、中文期刊文章、中文语境下的公开科普；不引商业测评机构文案，不出现他方品牌名；不引只有外文原版的条目。
2. 首批可引（开发前逐条核对，核对不到就不写）：

   | 来源 | 用途 |
   |---|---|
   | 威廉·莫尔顿·马斯顿《常人之情绪》（李海峰、肖琦、郭强 译，电子工业出版社，2018 年；英文原版 1928 年） | DISC 四分类的原始出处 |
   | 解伟《「李云龙式」干部 DISC 测评分析及使用建议》（《领导科学》2019 年第 20 期） | 中文语境下四类因子的读法与应用示例 |

3. 展开区底部固定一句：「以上为科普性说明，资料来自公开出版物，不构成学术定论；本测评不是临床心理测验。」
4. 禁止：不写「国际权威」「科学认证」「精准度 xx%」；不整段复制文献原文，一律转述；**不生成外站链接**，来源条目统一存进站内知识库（`web/kb.html`）。
5. 假设：若后续要补更多来源，先核实作者、标题、出处、年份四项齐全再写入 `content.js` 的 `REF_LIBRARY`。

#### 3.8.4 交互

1. 报告「四个维度」列表每行：`D · 支配` + 关键词 + 一句话释义，右侧「展开」按钮。
2. 点击展开：显示「生活里的你」「这个说法从哪来」「参考来源」三段；再点收起，按钮文案在「展开 / 收起」间切换。
3. 四条可同时展开，互不影响；默认全部收起；展开状态不写 `localStorage`，刷新后恢复默认。
4. 来源条目在站内知识库打开（`kb.html?ref=...`），**不生成外站链接、不新标签跳走**。
5. 展开 / 收起用按钮（可键盘操作），点击区域高度 ≥44px。

#### 3.8.5 不做的范围

- 不做逐题「题目依据」、不做 12 类型来源、不做参考文献页 / 引用格式管理。
- 不做 AI 生成的动态解释；文案静态维护在 `content.js`。

**现状（v0.19 已改）**：`DIM_DETAILS` 提供每维「生活里的你 / 这个说法从哪来 / 参考来源」；来源为 2 条中文条目（《常人之情绪》中文版、《领导科学》2019 年第 20 期文章），点开进站内知识库对应条目，不外跳；展开区底部固定「科普性说明，不构成学术定论」。

### 3.9 数据管理（P0）

入口：首页底部、历史列表页底部各一个「数据与隐私」。

- 导出：下载 `work-persona-backup-YYYYMMDD.json`，内容 `{ app, schemaVersion, exportedAt, settings, draft, history }`。
- 导入：选择 JSON 恢复，先提示文件里的条数、确认后覆盖；冲突时以文件为准；非法文件不写入。
- 清除：连续两次确认后删除历史 / 草稿 / 昵称；已登录用户额外提供「同时删除云端档案」（P1）。
- 隐私说明：数据只存本机、换设备或清浏览器会丢、登录只显示昵称、结果不构成诊断。

### 3.10 云端同步（P1，接入统一账户中心）

**身份与边界**
- 登录态统一由账户中心提供（整文件复制 `ps-auth.js`），`productId = work-persona`，站点 `https://persona.chesterlee.cn`（登记时以实际子域为准）。
- 账户中心**只提供身份**：不向其写入任何题目答案、分数、报告、昵称以外的内容。
- 同步数据落在同机独立同步服务（Node + SQLite），以账户中心 `uid` 作主键；单 uid 单档案 ≤ 256 KB。
- 未登录仍可完整答题、看本地历史；只有「跨设备同步」需要登录。
- 登录后自动开启同步（每台设备首次登录即拉取并合并）；用户主动「关闭同步」或「删除云端档案」后，该设备不再自动开启，直到手动再点「开启同步」。

**登录入口**
- 首页右上角 + 「设置 / 关于」页各一个入口：未登录显示「登录」，已登录显示昵称。
- 同步状态三态：已同步（显示时间）/ 本地有改动待同步 / 同步失败（可重试）。
- SDK 加载失败或账户服务不可用时：隐藏入口，本地功能照常，不阻塞答题。

**同步内容**
- 云端一条档案：`{ schemaVersion, uid, settings, draft, history, updatedAt }`
  - `settings`：昵称与偏好，带 `updatedAt`。
  - `draft`：`{ answers, cursor, stage, updatedAt, version }`。
  - `history`：数组，每条含唯一 `id`（`时间戳-随机串`）、完成时间、类型代码、三状态分数。
- 范围：历史 + 设置 + 未完成草稿；分享图 / 导出文件不同步。

**合并规则（后写覆盖 + 历史去重合并）**
- `settings` / `draft`：比较 `updatedAt` 取较新；完全相同则保留云端。
- `history`：按 `id` 去重取并集；同 id 取 `updatedAt` 较新；按时间倒序，最多保留 50 条。
- 合并后档案版本 +1，结果同时写回本地与云端。
- 冲突不弹窗打断，只在同步状态区提示「已合并」。

**触发时机**
- 登录成功 / 打开已登录页面：先拉取 → 合并 → 按需推送。
- 完成测评、修改设置、退出答题：立即推送（节流）。
- 答题过程中：每 5 题或每 60 秒推送一次草稿（先到者触发）。
- 推送失败：标记 `pending`，下次登录 / 打开页面 / 网络恢复时重试，最多退避 3 次。

**接口**
- `GET /wp-sync/load`：Bearer Token，服务端校验后取 uid。
- `POST /wp-sync/save`：body 带 `baseVersion`；版本不一致返回 `409` + 当前档案，客户端合并后重试一次。
- `DELETE /wp-sync/profile`：删除云端档案（二次确认）。
- `GET /wp-sync/healthz`。
- 限流：单 uid 写 ≤10 次/分钟；payload ≤256 KB；日志只记 uid 哈希与状态码，不记内容。

**隐私与删除**
- 登录即自动同步，数据页用一句话说明「按统一账户 uid 保存历史/草稿/设置，可随时关闭或删除」。
- 「清除我的数据」提供两选项：仅清本机 / 同时删除云端；删除后各设备刷新即不可见。
- 验收时确认：账户中心后台检索不到任何测评内容。

**不做**
- 匿名同步码、多人协作、团队排行、公开分享链接、在账户中心内存储业务数据。

> 已核对（2026-11-10）：同步服务不本地验签，按接入契约转调账户中心 `POST /accountCenter {action:'me'}`（Bearer Token）取 uid，结果缓存 5 分钟（key 为 token 哈希）；401 → `UNAUTHORIZED`，429 → `RATE_LIMITED`，连不上 → `503 ACCOUNT_UNAVAILABLE`。

### 3.11 关于页（P0，已完成 v0.17）

- 入口：首页底部「关于三面」。
- 内容：版本与更新日期、「这是什么」（定位 + 不做什么）、「怎么用」（3 条）、「数据与账号」（3 条 + 打开数据与隐私）、「边界」（复用固定声明）、页脚品牌与站点名。
- 文案全部静态维护在 `content.js` 的 `APP` 段，版本号与发布日期同源。

### 3.12 参考知识库（P0，已完成 v0.19）

**要解决的问题**：报告里的来源原来是一条外站链接，点开就跳出站、还是英文条目。改成「中文来源 + 站内直接读」，并把来源沉淀成可维护、可补充的知识库。

#### 3.12.1 页面与入口

- 独立页面 `web/kb.html`，零依赖、可双击打开；从报告「参考来源」带 `?ref=<条目 id>` 进入，自动展开并定位该条。
- 首页底部「参考知识库」也可进入；页头「回到测评」返回首页。

#### 3.12.2 条目

| 项 | 要求 |
|---|---|
| 必备字段 | 标题、类型（书目 / 文章 / 网页 / 其他）、说明正文 |
| 选填字段 | 出处（作者 / 刊物 / 网站 / 年份） |
| 预置条目 | 存在 `content.js` 的 `REF_LIBRARY`，全部中文；正文为编辑转述，不摘抄原文 |
| 展示 | 标题 + 类型标签 + 出处 + 一句摘要；「展开全文 / 收起」看完整正文与编辑注 |
| 外链 | 条目内**不出现可点击外链**，不新标签跳走 |

#### 3.12.3 手动加入来源

- 「＋ 加入参考来源」展开表单：标题（必填）、类型、出处（选填）、说明（必填，≤500 字）。
- 保存到本机 `localStorage: wp_kb_refs`（上限 100 条），立刻出现在列表并自动展开；条目带「本机添加」标记，可单条删除。
- 写入失败（隐私模式 / 空间满）在表单内提示，不丢已填内容之外的数据；不做云端同步。
- 说明页底部固定一句：条目按中文撰写、只作科普、不构成学术定论、不是心理诊断。

#### 3.12.4 不做的范围

- 不做上传附件、全文检索、标签体系、多人协作、云端共享；不做外部链接托管与引用格式管理。

### 3.13 AI 润色报告文案（三期，规划中，未排期）

**要解决的问题**：现在的报告是「规则 + 固定文案」查表拼装，同类型的人拿到的句子完全一样，读起来像模板。三期想让报告更个性化、更像人写的，但**不改变测评本身的判定逻辑**。

#### 3.13.1 硬边界（不可越）

| 项 | 要求 |
|---|---|
| 分数来源 | 仍是本地 `score.js` 纯函数计算，AI **不参与打分、不改类型、不改位移** |
| 上传内容 | 只发「三段四维分数 + 类型代码 + 主/次/低维 + 位移」这些**结构化数字与代码**；**绝不上传答题原文、选项、草稿、历史、昵称** |
| 输出用途 | AI 只负责把已有结论**换句说法**，不得新增结论、不得推断人格障碍、不得给职业建议以外的判断 |
| 降级 | 未登录 / 无网 / 调用失败 / 超时（≤8s）时，自动回退到现有规则文案，页面不报错、不卡住 |
| 留痕 | 报告需标明「文案由 AI 润色」字样；历史详情存**当时生成的文案快照**，不重算 |
| 合规 | 页面口径不变：科普性说明、不作招聘/晋升依据、不构成心理诊断 |

#### 3.13.2 Key 与调用方式

- **用户不填 Key**：Key 由统一账户中心托管，前端通过 `PSAuth.aiKeyCall('chat', …)`（见 `ps-auth.js` §AI Key 托管）走统一网关，Key 不出服务端。
- 未登录用户不出现任何 Key 输入框，直接走规则文案；登录后才有「AI 润色」选项。
- 调用限流：单用户每日上限（初定 20 次）+ 同一份结果重复润色命中缓存（按分数指纹），避免刷额度。

#### 3.13.3 展示与交互

- 报告页顶部给一个开关：「标准版（规则文案） / 润色版（AI 改写）」，默认标准版，避免默认消耗额度。
- 切换润色版时显示「正在润色…」，失败则提示一句「暂时用标准版」并保留开关状态。
- 润色只作用于「特征句 + 状态画像 + 位移解读」三块；分数、图表、类型名、来源、免责声明一律不改。

#### 3.13.4 不做的范围

- 不做多轮对话、不做报告问答、不做 AI 出题、不做 AI 改写题目与类型名。
- 不把测评结果写进账户中心；润色缓存与文案快照只落在本机 / 自有同步服务。

#### 3.13.5 验收标准（届时补）

- 断开网络后切到润色版：8 秒内回落标准版，报告内容完整可读。
- 抓包核对：请求体只含分数与类型代码，不含任何题干与选项文本。
- 同一份结果连续润色 2 次，第 2 次命中缓存、不新增额度消耗。
- 未登录用户全程看不到 Key 输入框，报告与现在一致。

## 5. 技术方案

| 项 | 方案 |
|---|---|
| 形态 | 纯静态：`web/index.html` + `assets/css/style.css` + `assets/js/{questions,content,app}.js` |

| 维度说明 | `content.js` 的 `DIM_DETAILS`（每维 `life / origin / sources[{refId,label}]`）；`app.js` 渲染维度行时加展开按钮与折叠面板；CSS 新增 `wp-dim-*` 样式；纯静态文本，无网络请求 |
| 参考知识库 | `content.js` 的 `REF_LIBRARY` 存预置中文条目；`web/kb.html` + `assets/js/kb.js` 渲染列表与「加入来源」表单；本机条目存 `localStorage: wp_kb_refs`；CSS 新增 `wp-kb-*` 样式 |
| 账户 | `web/assets/js/ps-auth.js` 整文件复制自账户中心，不手改；`productId=work-persona`，`returnUrl` 指向 `https://persona.chesterlee.cn` |
| 同步服务 | 同机独立 Node + SQLite（`server/`），表 `wp_profiles(uid, payload, version, updated_at)`；反代 `/wp-sync/*`。落地为 `server/wp-sync.js`（`node:http` + `node:sqlite`，零依赖）+ `web/assets/js/sync.js`（客户端 `WPSync`）；环境变量 `PORT`(8944) / `HOST`(127.0.0.1) / `DB_FILE` / `ACCOUNT_CENTER` / `ALLOWED_ORIGINS` |
| 图表 | Canvas 2D 手绘折线 |
| 分享图 | Canvas 2D → `toBlob` → 下载 |
| 部署 | 静态文件放已备案子域目录；同步服务与账户中心同机部署、独立进程 |
| 日志 | 统一 `log()` 前缀 `[wp]`，默认只在控制台，不弹窗；同步日志不记录档案内容 |

## 7. 成功标准

1. 完成率 ≥70%（50 人样本内自测）。
2. 盲测 ≥4/5 认为结果「像我」。
3. 2 周重测，主维不漂移。
4. 手机微信内可打开，草稿不丢。
5. 全部文案原创，无整句与他人产品相似。
6. 跨设备：A 设备完成测评后，B 设备登录 10 秒内看到同一 `history.id`。
7. 未登录或同步服务不可用时，答题、计分、报告、本地历史均不受影响。
8. 账户中心数据中检索不到任何测评内容，只有 uid 与昵称。
9. 完成测评后关闭页面再打开，首页「历史记录（N）」能看到该条，点开可完整复看当时报告。
10. 重测后，最新记录详情显示与上一条的主维 / 类型代码 / 最大位移对比；首次记录显示「暂无对比」。
11. 历史超过 50 条时只保留最新 50 条，最旧一条被淘汰；删除草稿但不影响历史。
12. 报告「四个维度」每条都能展开，展开后能看到生活表现、来源说明与至少 1 条中文来源。
13. 四条来源点开后都在站内知识库内展开对应条目，不跳出站点、不出现失效外链；展开区固定显示「科普性说明，不构成学术定论」。
14. 知识库「＋ 加入参考来源」填标题与说明即可保存，刷新后仍在；可单条删除；页面无外站跳转。
15. 找 1 位非专业用户通读，能用自己的话复述四个维度分别是什么意思，不需要再问「这是什么术语」。

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 题目不像本人 | 纸面盲测先行；不过关就重写题库，不写代码 |
| 完成率低 | 自动存档 + 续答 + 分段反馈 + 时长预告 |
| 草稿丢失 | 导出/导入兜底；P1 登录后同步草稿到云端 |
| 文案被指抄袭 | 逐句原创 + 发布前逐句比对 |
| 结果被误用 | 页面显著位置写「不作招聘/晋升依据」 |
| 合规口径 | 不出现诊断/治疗/精准度承诺；不用他方商标 |
| 范围膨胀 | 一期只做个人报告，团队与三合一进二/三期 |
| 账户中心不可用 / 登录失败 | 同步入口隐藏，本地答题与报告不受影响；恢复后自动重试 |
| 业务数据越界写进账户中心 | 硬约束：账户中心只换 uid，档案只进独立同步服务；验收时逐项检查 |
| 两端同时答题导致草稿互覆盖 | 按 `updatedAt` 取新；被覆盖版本仍留在本机导出文件中；状态区提示「已合并」 |
| 历史把 localStorage 写满 | 上限 50 条 + 写失败时降级保留最新记录并提示用户清除/导出，不静默丢数据 |
| 同一毫秒连续完成导致记录互相覆盖 | `id` 用「时间戳 + 随机串」，写入前按 id 去重 |
| 历史结构升级后旧记录读不出 | 记录带 `schemaVersion`，读取时过滤无效项，不因单条坏数据导致整个列表打不开 |
| 历史详情重新计分导致与当时结果不一致 | 详情一律渲染记录快照，不重新计分 |
| 来源写错 / 条目与标注不一致 | 上线前逐条核对作者、标题、出处、年份；核不到就删，宁可少引 |
| 知识库手动条目写错或带广告 | 只存本机、明确标注「本机添加」、可单条删除；预置条目由编辑维护 |
| 被误解为「学术认证 / 精准测评」 | 展开区固定免责声明；不写权威、认证、精准度等词 |
| 说明太长没人看 | 默认折叠、每维 ≤200 字，先给生活场景再给来源 |
| 来源文案与他方重合 | 只转述不摘抄，发布前逐句比对 |
| 域名 / CORS 配错导致登录回跳失败 | 按接入清单登记 `persona.chesterlee.cn`，同步服务域名加入 `ALLOWED_ORIGINS` 并重启 |
| 同步拖慢答题 | 推送节流 + 失败退避，主流程不等待同步结果 |
| AI 润色把结论说跑偏 / 说成诊断 | 只允许改写已有句子；prompt 锁死结论、禁用诊断词；输出做关键词拦截，命中即回落规则文案 |
| AI 润色泄露隐私 | 请求体只允许分数与类型代码，禁止题干/答案/昵称；上线前抓包核对 |
| AI 额度被刷 / 成本失控 | 登录后才可用 + 每日上限 + 结果指纹缓存；默认标准版不自动调用 |
| AI 服务不可用拖垮报告 | 超时 ≤8s 自动回落标准版，开关状态保留 |
